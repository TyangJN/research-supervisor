# 路线 B：先证明评估缺口，再扩大数据集

用户路径：发现不足或新问题 → 构建初步数据集 → 验证必要性 → 完整构建。必要性包括问题是否重要，以及新增数据是否提供现有资源无法低成本获得的判断。

推荐路径：**现象/需求 → 要测的能力或条件 → 对照现有评估 → 最小诊断集 → 必要性与测量验证 → 扩大/修订/复用/停止 → 完整构建与独立评估 → 数据或 benchmark 贡献。**

先区分新训练数据、评测集、诊断集、现实观测数据。下面偏评测/诊断；训练数据的必要性要看训练后在独立评估上的增量价值、与已有数据或简单增广的比较及成本，不强套模型排名变化。

## 1. 把“新”变成具体缺口

明确对象、能力/构念、使用条件与后果：现有测试会让人误以为系统能做什么，实际在哪种重要条件下不能？这会影响什么科学或应用判断？

对照最近邻的数据集与协议，检查是否已有相应子集、标签、切片、挑战集或可行重分析。领域/语言/规模变化不是自动成立的贡献；覆盖遗漏的重要群体、语言或真实场景可以有价值，但需解释现有证据为何不能迁移。

未检索到不证明没有。记录检索边界；缺少全文不声称知道构建细节。无法检索时可先设计诊断，新颖性判断保持待核验。

## 2. 构建最小但能诊断的数据

试点回答必要性与可测性，不是提前完成缩小版大工程。按关键因素覆盖与成本决定规模，样本数是设计选择而非合格线。

按任务需要包含：

- 目标现象与相近的正常/对照情况，区分目标能力和一般难度。
- 来源与选择理由、目标因素和干扰因素、答案/评分依据。
- 独立标注、复核或专家依据；记录歧义、分歧与修订，未经核验的合成答案不是金标准。
- 覆盖差异的参考方法、简单捷径，必要时的人类/专家或任务规则对照。
- 可比的预算、输入信息和指标协议，以及实际任务的失败边界。

诊断样本可有意采样极端情况，但不能据此估计现实发生率。不要只收集已知模型答错的例子来证明困难；如果对抗性构建就是目标，应明示并另查迁移性和选择偏差。

## 3. 扩建前回答三类问题

| 判断 | 有帮助的证据 | 不能单独证明 |
|---|---|---|
| **必要性**：现有评估漏掉重要内容吗 | 具体需求；旧结论在新条件失效；已有子集无法回答；纠正重要认识 | 模型低分、搜索没命中、规模更大 |
| **有效性与可靠性**：测到目标了吗 | 控制干扰；答案/评分可验证；分歧可解释；捷径检查；评价稳定 | 所有模型都失败、题目难、LLM 生成答案 |
| **新增用途与可行性**：扩大增加什么知识 | 可解释的错误维度、能力边界、区分原来混淆的方法或支持具体决策；成本质量可控 | 必须改变排名、配套新模型或达到固定规模 |

排名不变不自动说明无价值，可能揭示共同盲区或真实使用限制；排名翻转也不自动说明有价值，可能来自噪声、错误标注或协议差异。依据明确用途和可信证据判断。

## 4. 作出阶段决定

- **扩大**：试点支持重要缺口、测量可信，扩大可改善覆盖、精度或研究问题的回答。说明证据与剩余风险。
- **先修订**：问题可能重要，但标注、评分或控制不足。先修最影响判断的因素，再做有区分力的试点。
- **复用/扩展**：现有资源的子集、重标注或新协议已足够，不强造新集；其贡献另行评估。
- **缩小/停止**：缺口已覆盖、测不到目标、成本不可承受，或扩大不再改变决定。保留学到的内容。

用户要完整方案时可交付带条件的分阶段方案，不把尚未验证的必要性写成事实。用户明确选择继续时保留其决定与证据边界，不反复阻拦已授权、可逆的准备工作。

## 5. 完整构建

规模由覆盖、统计精度/分层需求、独立单位与成本推导。先定义群体、场景和采样框架，再估算样本，不先拍总数再找理由。

按需覆盖：数据来源与使用范围、采集/生成、标注与复核、重复与污染、难度与目标因素、分组/时间/来源划分、版本与变更、评价代码和成本。

试点已用于选择问题或方法，应标为探索/开发材料。确认评估尽量使用独立来源或未参与选择的样本；做不到时解释限制并降低泛化主张。合成数据需检查生成器偏好、模板泄漏与循环评价，不以生成模型自评代替独立验证。

若新发现涉及稳定机制，可转路线 A 研究改进。仅在需要验证用途时加入轻量方法，不默认要求 benchmark 同时贡献复杂新算法。

## 6. 最终贡献

论文围绕评估缺口、设计原则、构建和质量证据、协议、可信发现及边界组织。大小、排行榜和多模型表格服务研究问题。拟公开数据或投稿时执行用户授权内的准备，不自动发布。

## 示例：仅示范判断

怀疑现有图表问答忽略图例和坐标歧义。先查可重用子集，再做有歧义/无歧义的匹配对。复核歧义是否真实、答案是否唯一、专家是否也有分歧。若低分主要源于错误金标准，先修标注；若控制难度后仍有可解释差异，并改变对能力的认识，再扩大覆盖。
