# 路线 A：从现有数据集发现问题，再形成方法贡献

用户路径：找数据集 → 找方法 → 试验并发现问题 → 改进 → 论文。保留这一入口，将证据判断嵌入过程，不把它变成必须顺序走完的清单。

推荐路径：**任务与候选数据 → 合适的参考方法 → 可解释的运行与错误分析 → 候选问题 → 区分解释的小实验 → 针对性改进 → 独立验证 → 贡献与论文。**

## 1. 数据集代表什么

已有数据时先利用已有材料。需要选数据时围绕目标定向找候选，不以下载量、榜单热度或模型低分作为唯一理由。

判断可能改变选择的条件：

- 任务输入、输出、用户或科学对象，数据中什么现象值得研究。
- 来源、标注含义与质量、采样覆盖、划分和指标是否代表目标能力。
- 数据能否获得和用于当前研究；代码、协议与所需资源是否可用。
- 重复、泄漏、时间失配、分布偏差或指标饱和是否妨碍回答问题。
- 规模是否足以支持当前探索，是否有独立样本用于后续确认。

输出带理由的选择及限制即可。先选数据只是起点；缺少任务意义时提出候选问题，不迫使用户先承诺尚未验证的宏大故事。

## 2. 方法选择服务诊断

按需要包含简单而合理的参照、代表性方法、相关强方法。依据是问题覆盖、可比性和资源，不是“必须最新”或固定数量。较旧但有效的简单方法仍有诊断价值；无法复现的最新系统记录其限制。

先检查任务/指标实现与划分，再复现可用参考结果或解释差异。记录模型、数据版本、训练/推理条件、调参范围和成本。不要求达到论文原分数才允许探索，但异常结果先定位，不能直接算作方法缺陷。

## 3. 从失败现象到研究问题

不只看平均分。结合任务观察错误类型、场景/群体、输入属性、难度、成本、置信度或训练动态；只选择能回答问题的维度。

| 问题 | 需要的材料 |
|---|---|
| 现象是什么 | 具体实例、可复查结果和评价条件 |
| 是否反复出现 | 独立样本或适合任务的重复观测；范围和不确定性 |
| 为什么值得研究 | 错误的影响、揭示的未知或已有方法的边界 |
| 是否已有解释/修复 | 近邻工作、简单修复和反例 |
| 可能为什么发生 | 少量可区分的解释，而非先选模块再编原因 |

“模型在这批样本上低分”是观察；“缺乏组合泛化”是候选解释；“加入模块 Z”是方法选择。三者之间都需要证据连接。

从开发数据发现切片时明确探索性质。不能把人工挑选的困难例子描述为代表性样本，或把同一批数据同时用于发现问题、选择方法和证明最终优势。

## 4. 先做区分解释的小实验

围绕最影响选题的未知，比较合理替代解释，例如标签/解析问题、缺少信息、提示或调参差异、表示限制、数据分布或机制不足。不要求每项课题检查所有项。

优先比较关键因素不同而其他条件相同的情况，或用负对照排除简单解释。样本量、重复次数和成本按效应、噪声与决策需要选择，不设通用合格数量。

- 简单修复消除问题：承认原机制解释变弱；修复或纠正现有评估是否有独立贡献，再另作判断。
- 现象稳定、替代解释不足且有可检验机制：进入针对性改进。
- 数据不能观测关键因素：转路线 B 做最小诊断集，先验证必要性。
- 缺乏重要性、已有工作充分解决或资源不可达：建议缩小或停止当前版本，给出理由。

## 5. 改进回应已识别的问题

优先尝试最简单、足以检验机制的改变。说明它作用于什么、为什么预计有效、在哪些条件下应无效或失效。允许探索多个方法，不以模块堆叠代替机制推理。

分别回答**有没有实际收益**与**收益是否来自所声称的机制**。消融、匹配成本的对照、误差分析或干预用于回答后者；总体提升不足以证明归因。

开发期反复使用的数据不再承担未触碰测试集的角色。最终验证范围与贡献匹配：仅声称本场景改进不强求跨领域；声称泛化、稳健或效率时提供相应比较与不确定性。详见 [证据与实验](evidence-and-experiments.md)。

## 6. 研究结论与投稿

方法未胜出时，区分实现、测量、比较与假设问题。可靠负结果或简单方法解释复杂系统的现象可能有贡献，但不承诺必能发表。

论文回答：发现什么、已有工作未解释/解决什么、证据是什么、方法带来什么、边界在哪里。可以提前草拟论文逻辑，不能提前写出虚构结果。

## 示例：仅示范推理，不是已有结论

在已有文档问答数据集上，观察到跨页问题错误较多。先检查标注、检索是否拿到必要页面、输入长度和评价脚本。若给定正确页面仍失败，再区分实体关联、证据组合与推理等解释；若只是检索缺页，就研究检索覆盖，不能直接命名为“推理能力不足”。针对已确认限制改方法，再用未参与选择的样本检验。
